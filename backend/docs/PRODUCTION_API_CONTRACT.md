## Shared behavior

- Success uses the existing `ApiResponse<T>` envelope (`data` contains the typed value); collection queries use `items`, `pageNumber`, `pageSize`, `totalCount`, computed `totalPages`, and optional unit-safe full-filter `summary`. Page size is clamped to 1–200.
- Errors use the existing envelope: 400 invalid data/precision; 401 missing authentication; 403 insufficient permission or company scope; 404 scoped missing source; 409 stale version/plan, invalid transition, source duplication, shortage or idempotency conflict. Stable `conflictCode`, optional `currentVersion`, and `reloadRequired` are included where available. Reload the source after every conflict; do not substitute an old version.
- DateOnly fields are `yyyy-MM-dd` business dates. Completion timestamps carry explicit offsets. Audit creation times remain UTC. Decimal posting values support six places; source import quantities support twelve. Null means unavailable, never zero.
- Company and actor are server context, absent from client write authority. Tokens must carry the configured catalog company claim.
- The command result `id` is the source result identity; purchase receipt returns identify the physical return, and credit results identify the existing PurchaseReturn financial document. Check the route contract before using an ID in another command.
- Operational report kinds are `stock-as-of`, `ledger`, `scorecard`, `plan-actual`, `capacity`. Stock-as-of requires `asOfDate`; current PO follow-up requires the current configured business date.
- Production import dispositions: HistoricalProduction1, HistoricalDispatch2, DemandAggregate3, Opening4, MasterReference5, PendingPurchase6, EvidenceOnly7. Mapping is not posting authority. Flow: stage → preview/map → validate → reconcile → approve → post selected safe rows.
- Existing CSV export root is `POST /api/v1/reports/export` with reportId `manufacturing-history` or `manufacturing-consumption`, format csv and matching filters. This route is outside the controller inventory below; its actual root is verified in ReportExportsV1Controller. Operational exports are NDJSON.

## Frontend handoff

Existing clients are `frontend/src/services/manufacturing/manufacturingService.js` and `frontend/src/services/reports/manufacturingReportsService.js`; the latter uses the authoritative report routes above. Update consumers from the generated schema, not from workbook formula labels. UI local manufacturing preference never authorizes a server transaction. Use returned IDs/versions, preserve decimal precision until the server boundary, show unavailable data distinctly, and never infer invoice stock ownership from a header association.

New order/configuration/capacity/import endpoints need their corresponding product screens before a complete end-user workspace can be claimed. Swagger contracts and backend journeys are the backend deliverable; existing report/BOM/Item screen integrations are included.

Regenerate these fixtures with `COSMOS_WRITE_PRODUCTION_CONTRACTS=1` and the `ProductionSwaggerRuntimeTests` filter. The factory forbids SQL connections and replaces startup provisioning; this proves real route/schema construction and unauthenticated boundaries only.
