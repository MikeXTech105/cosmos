# Project Progress

## 2026-08-14 — Website Announcement Paging Mapping Fix

Resolved the Website Management Announcement list runtime Dapper materialization failure. The deployed `dbo.usp_WebsiteAnnouncement_GetList` procedure matches the source migration and returns the 14-column list shape: `Title`, `CtaLabel`, `CtaUrl`, `StartsAtUtc`, and `EndsAtUtc` are nullable; `DismissalVersion` is non-null; `RowVersion` is `VARBINARY(8)`; and `TotalCount` is pagination metadata. The repository had queried that shape directly into the 13-parameter positional `WebsiteAnnouncementDto` and used reflection to retrieve paging metadata, leaving Dapper unable to find a compatible constructor. List procedures now materialize into internal persistence rows and map explicitly to public DTOs; `TotalCount` belongs only to `PagedResult`. The correction also covers Website Product, Blog Post, and Warranty Claim paged lists, which shared the unsafe generic pattern. No SQL repair migration was needed. Focused Dapper-contract, mapping, and empty-list controller tests were added. The complete build passed and the full test suite passed 223/223. Read-only staging verification confirmed all four Website Management paged procedure definitions and result-column lists match the source migration; the Announcement procedure executed successfully with zero current rows. The locally built API then returned HTTP 200 for an authenticated `GET /api/v1/website-management/announcements` request, with empty items and `TotalCount` 0, and the Website Management Swagger document returned HTTP 200 with the route present. No database data was modified.
