CALCULATION CONTRACT: 16 FAMILIES
Use precise decimal arithmetic on the backend. Frontend previews use the same documented rules and are never authoritative. Every result carries units, input period, as-of business date, source IDs, calculation version, freshness, policy and rounding explanation. Do not sum KG + PCS + ROLL or unlike finished units. Counts, money and quantities need distinct aggregation rules.

C01 Unit normalization and packaging.
BaseQty = SourceQty * VerifiedFactor(source unit -> Item base unit, effective on event).
Persist the factor on posted lines; future pack edits must not rewrite historical quantities. Reject cross-dimension or missing conversions. Keep pack size/units-per-box separate from BOM output basis. Where source demand is PCS and target base is BOX with 11 PCS/BOX, 330 PCS = 30 BOX; where base is PCS, 10 BOX = 110 PCS. KG, PCS and ROLL can all be legitimate base units. Never fabricate factor=1 for missing packaging.

C02 Versioned BOM, waste and actual consumption.
ExpectedComponent = FinishedBaseQty / BomOutputBaseQty * ComponentBaseQty.
Include approved component waste exactly once. ExpectedWithWaste = ExpectedComponent * (1 + WastePercent/100) when the BOM uses additive waste; do not confuse this with a yield-loss divisor. Keep planned requirement, staged issue, material return, actual consumed, material scrap and accepted/rejected finished output distinct.
Conditional verified example: BH25 has 11 PCS/BOX, 13.090 KG/BOX -> 1.190 KG/PCS; 110 PCS require 130.900 KG; with additive 2% waste, 133.518 KG. Eleven inner boxes per output box means one inner box per PCS, not 11 per PCS. Freeze the approved BOM version and conversion snapshot at release, including effectivity, and validate as-of dates.

C03 Inventory ledger, reservations and balances.
OnHand(asOf) = approved opening + signed posted movements up to the defined business-date cutoff.
FreeStock = OnHand - active owned reservations - blocked/unavailable stock, subtracting each exclusion exactly once according to the actual inventory model.
AvailableToOrder = FreeStock + the same order's existing valid reservation when recalculating its own feasibility.
Release adds reservation; it does not alter OnHand. Completion consumes the attributable reservation and posts actual consumption/accepted output together. Extra actual consumption needs an availability check; shortages cannot silently overdraw another order's reservation. Final close releases only unused reservation. Historical reserved quantities require historical events/snapshots, not today's ReservedStock. Reconcile any stored CurrentStock/ReservedStock cache to the ledger; prohibit arbitrary API field edits that bypass controls.

C04 Demand, cover and finished targets.
For verified demand quantity Q over N calendar days, DailyDemand = Q/N. Keep zero-demand, unavailable-demand and stale-demand different. Normalize a verified observed period to Monthly30 = DailyDemand*30. Aggregate demand must not be split into fictional daily transactions.
FinishedTarget = DailyDemand*21; WarningThreshold = DailyDemand*15.
CoverageDays = sellable stock / DailyDemand when DailyDemand > 0; with zero demand show an explicit no-demand state, not infinity/zero as a misleading metric.
The workbook's display conventions are MonthlyBoxes=ceil(Q30/B), HalfMonthBoxes=ceil(Q30/(2B)), FourWeekSliceBoxes=ceil(Q30/(4B)), Target21Boxes=ceil(21*Q30/(30B)). That "weekly" source column is a four-week slice, not an actual 7-day forecast. Label it accurately; operational 7-day demand is DailyDemand*7. Do not round the daily average before multiplying a horizon. Apply whole-pack constraints only at the execution/suggestion boundary where the item policy requires them.

C05 Finished-goods production netting.
Within a stated horizon, project stock using dated eligible receipts/open released output, reservations/commitments and demand exactly once.
SuggestedProduction = max(0, required horizon demand/target + distinct commitments outside that demand - eligible projected supply), with a documented forecast/order netting policy.
Orders already represented by aggregate demand must not be added a second time. Distinguish "open order output" from a posted completion already in OnHand. Deduplicate linked demand, inbound and production IDs. A horizon-average suggestion and a dated fulfillment projection are different views; show each basis. As-of snapshots must be stable and recomputed before release.
For the workbook-style 21-day top-up, do not add a second full 21-day forecast on top of the 21-day target. Use eligible unblocked physical supply plus distinct inbound/open output; when a commitment is already in requirement demand, do not also subtract its reservation from supply. If a dated projection deliberately carries an ending safety target beyond forecast demand, label that separate policy and horizon explicitly rather than silently turning this target into 42 days. Example: target 231 PCS, physical eligible supply 100 PCS and distinct remaining released output 40 PCS -> suggestion 91 PCS.

C06 Material explosion and feasible output.
Explode only remaining unproduced quantities against the frozen applicable BOM. Aggregate shared components in base units. Exclude cancelled/closed requirements, already consumed quantities and duplicated forecast/order demand.
For one product, material-limited output = min over required components(available-to-that-order / component-per-output), respecting actual item output increments. Multi-product plans share one component pool; never promise every row the same available stock. Provide bottleneck and shortage explanations. Track proposed allocations separately from durable release reservations.

C07 Routing, resource eligibility and capacity.
Work Centre shift windows must respect the configured business timezone, overnight shifts, breaks, approved downtime and calendar exceptions. Reject overlapping capacity double counting. AvailableMinutes = usable shift minutes - reserved minutes/downtime, using the existing data model without double-subtracting breaks.
RequiredMinutes = setup minutes + runtime for the remaining operation quantity under its verified rate basis.
Units/minute, seconds/unit and injection cycles/shots with eligible cavities are different rate bases. Only convert shots to SKU output when the mould/cavity allocation is verified; shared/family moulds must not multiply the full output into each SKU. Carry setup/changeover rules, lot size, operation sequence and resource exclusivity. Show material-limited and capacity-limited plans separately. OEE monitoring is reused; no invented OEE score from absent telemetry.

C08 Raw-material demand, lead time and safety.
Separate actual material ledger consumption from future material forecast. Document which demand is already covered by firm production; do not add it twice.
If normalized 30-day requirement R30 is chosen, D=R30/30, Safety=R30/2, LeadDemand=D*LeadTimeCalendarDays, ReorderPoint=LeadDemand+Safety.
Example R30=3,000 KG and lead=2 weeks: D=100 KG/day, LeadDemand=1,400 KG, Safety=1,500 KG, ROP=2,900 KG.
Map the existing Procurement SafetyFactor deliberately: 0.5 means half-month only when RequirementQty is normalized to 30 days. A 10-day run's raw requirement must not be multiplied by 0.5 and mislabeled half-month.
Show physical, reserved, available, blocked, eligible inbound and projected inventory position separately. C09 Purchase shortage, MOQ and order multiples.
Shortage = max(0, ReorderPoint - EligibleInventoryPosition).
If Shortage <= 0: RecommendedPurchase=0 and no reorder alert.
Else Baseline=max(Shortage, MinimumOrderQty); if a valid positive order multiple M exists, Suggested=ceil(Baseline/M)*M; otherwise preserve valid unit precision.
Never round a positive fractional shortage to zero before applying MOQ. Apply whole-unit constraints only for that item's unit. MOQ is a minimum, not a multiple, and a source field labeled EOQ is not an economic optimization model.
At ROP=100, position=100, MOQ=50 -> 0. Position=99 ->50. Shortage=55, MOQ=50, multiple=12 ->60. No-demand with negative stock is a reconciliation exception, not a reason to hide shortage without review. No-demand with nonnegative position and ROP0 ->0.
